REAL extraction filters (what the queries actually applied):
                        >= 15 SAS observations per stay
                        >= 5 propofol infusion events per stay
                        rate > 0 (propofol)
                        SAS valuenum between 1 and 7
                        All four are hard-coded literals, repeated
                        independently in each of the three queries. Verbatim
                        text for two of the three is now in queries/; QUERY 2
                        (patients) is still outstanding. See Section 9.
                        The >= 15 count spans the WHOLE ICU stay and is eroded
                        by the downstream 72-hour window: only 1,441 of 1,490
                        patients still have 15 usable observations. See the
                        [HIGH] item in Section 9 and Section 11.1.
NO age filter was applied. MIMIC-IV contains adults only by construction, so
the cohort is de facto adult (verified: min age 18, max 93), but no explicit
age >= 18 predicate exists in any of the three queries. Do not describe one.

Age is COMPUTED, not raw. The queries use MIMIC's anchor-year adjustment:
    DATETIME_DIFF(i.intime, DATETIME(p.anchor_year, 1, 1), YEAR) + p.anchor_age
This must be stated in Methods; "age at admission" alone does not describe it.

Weight and height come from mimiciv_3_1_derived.first_day_weight and
first_day_height via LEFT JOIN, so both can be NULL.
    Verified in the extract: weight NULL for 18/1490 (1.2%),
    height NULL for 398/1490 (26.7%).
    01_build_features.py substitutes weight=75 kg and height=170 cm for these.
    The weight default feeds the PK rate conversion for those 18 patients;
    the height default is an ML feature only and touches over a quarter of
    the cohort. Both defaults belong in Methods.

MODELING requirement (separate from, and weaker than, the extraction filter):
                        >= 11 SAS observations
                        (11 = 10 for history sequence + 1 prediction target)
This is enforced in 01_build_features.py, not in SQL. It never binds, because
the extraction filter already demands 15. Do not present 11 as the cohort
inclusion criterion; it is a downstream modeling constraint.

--- ELEVELD 2018 PK/PD POPULATION PARAMETERS ---
Source: Eleveld DJ, Colin P, Absalom AR, Struys MMRF. Br J Anaesth.
        2018;120(5):942-959. doi:10.1016/j.bja.2018.01.018
V1        6.28 L        central compartment volume
V2        25.5 L        rapid peripheral compartment volume
V3        273 L         slow peripheral compartment volume
CL        1.79 L/min    metabolic clearance (hepatic)
Q2        1.75 L/min    inter-compartmental clearance to V2
Q3        1.11 L/min    inter-compartmental clearance to V3
ke0       0.146 /min    effect-site equilibration rate
EC50_pop  3.08 ug/mL    population EC50
gamma     1.47          Hill coefficient
E0        7             baseline SAS without drug

--- ODE SOLVER ---
Method                  scipy.integrate.odeint
Time grid               1 minute steps
Simulation duration     72 hours (sim_duration_hrs=72)
                        *** NOT ONLY A SOLVER SETTING. ***
                        sim_duration_hrs=72 is cohort-defining: it silently
                        determines which observations become usable data and
                        which patients survive into the analysis at all. It
                        discards 62.9% of extracted SAS observations and drops
                        one patient entirely. Treat it as an inclusion
                        criterion and report it as one. Full numbers in
                        Section 11.
Initial conditions      all compartments = 0
mxstep                  5000

--- EC50 CALIBRATION (the digital twin innovation) ---
Optimizer               scipy.optimize.minimize_scalar, method='bounded'
                        (Brent's method)
Bounds                  [0.5, 10.0] ug/mL
Objective               MSE between mechanistic prediction and observed SAS
Calibration set         first half of each patient's SAS observations
                        n_calib = max(SEQUENCE_LENGTH, n_obs // 2)
Fallback                if optimization fails, use EC50_pop (3.08)
WHY first half:         mimics clinical use, early observations personalize the
                        model before it predicts subsequent care. Also prevents
                        the calibration from seeing the prediction targets.

--- FEATURE ENGINEERING ---
SEQUENCE_LENGTH         10 (~2-4 hours of SAS observations)
Weight default          75 kg if missing or <= 0
Height default          170 cm if missing
Rate conversion         mcg/kg/min -> mg/min via (rate * weight) / 1000

Clinical features (10): age, gender (1=M, 0=F), weight, height, sas_last,
    sas_mean, sas_std, sas_trend, propofol_rate, time_hours
Static mechanistic (5): Ce, Cp, EC50_calibrated, mech_pred_pop, mech_pred_calib
Temporal derived for XGBoost (5): ce_seq_mean, ce_seq_std, ce_seq_trend,
    ce_seq_max, ce_seq_last
Sequence inputs for LSTM: 10-step SAS history, 10-step Ce history

--- ABLATION CONFIGURATIONS (5) ---
FULL_HYBRID       all features (reference baseline)
NO_TEMPORAL       remove temporal mechanistic features
NO_STATIC_MECH    remove static mechanistic features
PURE_ML           remove ALL mechanistic features (clinical only)
ONLY_MECH         remove clinical features (mechanistic only)

--- XGBOOST ---
n_estimators            100
max_depth               6
learning_rate           0.1
subsample               1.0
colsample_bytree        1.0
random_state            42
objective               reg:squarederror
Runs per config         1 (deterministic given fixed seed)

--- LSTM ---
Architecture            Input(seq) -> LSTM(units) -> Dropout(0.2) ->
                        concat(static) -> Dense(16, relu) -> Dropout(0.2) ->
                        Dense(8, relu) -> Dense(1)
                        Single layer, UNIDIRECTIONAL.
WHY unidirectional:     the task is forecasting; future observations are not
                        available at inference time.
Optimizer               Adam, learning_rate=0.001
Loss                    MSE
Batch size              64
Epochs                  50 FIXED (no early stopping)
Validation split        0.15
Seeds                   10, values 42-51 (BASE_SEED + 0..9)
Scaling                 StandardScaler, static and sequence scaled SEPARATELY
WHY fixed epochs:       April 2026 investigation found early stopping triggered
                        at wildly different points across seeds (18 to 50 epochs),
                        producing ~10% coefficient of variation. Fixed-epoch
                        training reduced CV to ~4%. This made results stable
                        enough to draw conclusions.

Ablation LSTM size      16 units (02_run_ablation.py, LSTM_UNITS=16)
Capacity sweep sizes    4, 8, 16, 32 units
Total sweep runs        4 sizes x 5 configs x 10 seeds = 200 LSTM runs

--- METRICS ---
Primary                 MAE (in SAS units, clinically interpretable)
Secondary               RMSE, R^2
Degradation formula     (config_MAE - FULL_HYBRID_MAE) / FULL_HYBRID_MAE * 100

7. VERSION HISTORY (the reasoning, not just the changes)
================================================================================

--- Jan 2026: project initialized ---
Chose MIMIC-IV v3.1 for public credentialed access and ICU coverage.
Chose Eleveld 2018 as the mechanistic foundation: current state of the art for
propofol, used in commercial TCI pumps, has calibratable population parameters.
Chose SAS as the target because it is consistently recorded in MIMIC; BIS was
considered and rejected because BIS is not reliably available in ICU settings.

--- Feb 2026: first hybrid experiment ---
XGBoost + mechanistic features vs pure XGBoost. Early result ~14.9% improvement
on a smaller sample. Robustness across training set sizes (10%-100%) showed the
hybrid won at every level.

--- Mar 2026: PHASE 1 - KIDNEY COMORBIDITY. NULL RESULT. ---
Hypothesis: patients with kidney disease benefit more from EC50 calibration.
Tested AKI, CKD 1-5, dialysis, diabetic nephropathy, hypertensive kidney disease.
RESULT: calibration improved everyone ~15-20% equally. No differential benefit.
t-test no-kidney vs severe-kidney: p = 0.45.
WHY IT FAILED: propofol is hepatically metabolized via glucuronidation, NOT
renally cleared. Kidney function does not substantially affect propofol PK. The
hypothesis rested on a flawed mechanistic assumption.
LESSON RECORDED: start from drug mechanism, not from data availability. The
cohort was chosen because MIMIC had good kidney flags, which is backwards.
An earlier 50+50 hand-selected analysis had shown 20% vs 10% (p=0.003); this was
almost certainly a small-sample false positive. Reported honestly, pivoted.

--- Apr 2026: PHASE 2 - EC50 CALIBRATION. WORKS. ---
Realized personalization does not require comorbidity. Per-patient EC50
calibration benefits everyone. This became the digital twin contribution.

--- Apr 2026: PHASE 3 - ALGORITHM-ARCHITECTURE MATCHING. FAILED. ---
Hypothesis: LSTM prefers temporal mechanistic features, XGBoost prefers static.
RESULT: both relied more on static; differences within noise (SD > mean effect).
Directional hypothesis did not hold. Failed to reject null again.
This framing is ABANDONED. Any document still describing it is superseded.

--- Apr 2026: LSTM STABILITY INVESTIGATION ---
Multi-seed runs showed MAE ranging 0.35-0.45 across seeds. Root cause: early
stopping triggering at very different epochs (18 to 50). Switched to fixed
50-epoch training. Coefficient of variation dropped ~10% -> ~4%.

--- Apr/May 2026: PHASE 4 - CAPACITY SWEEP. THE DISCOVERY. ---
Noticed in the failed ablation that FULL_HYBRID LSTM (most features) performed
WORST at 16 units. Classic overfitting signature.
Hypothesis: small LSTMs benefit from mechanistic features as physiological
priors; large LSTMs have enough capacity without them, so the same features
become noise.
Ran 4/8/16/32 units x 5 configs x 10 seeds = 200 runs, ~3 hours overnight.
RESULT: clean monotonic decay, 10.4% -> 4.5% -> 0.7% -> 0.6%.
This became the paper's headline.

--- May 2026: repository restructuring ---
Reorganized into a publication-ready structure. Local execution pipeline built.
SQL query templates created (but see GOTCHAS - the real queries were not saved).

--- Jun 2026: verification pass ---
Located capacity_sweep_results.csv on the experiment branch. Verified every
paper number against it. All matched. Computed formal trend statistics.
Discovered the 16-unit table inconsistency (see OPEN ITEMS).

--- Sep 2026: provenance pass ---
Created this file at the repo root. Corrected the repository visibility (it is
PUBLIC, not private) and audited the history for patient data (clean). Merged
experiment/lstm-capacity-sweep into main. Recovered the exact run timestamps for
both the 16-unit ablation and the capacity sweep from the run logs, and recorded
the sweep commit hash, the machine specs, and the exact installed package
versions. Recorded, but did not resolve, the src/ script-inventory discrepancy.

--- Sep 2026: SQL recovery pass ---
The real BigQuery SQL was reviewed and its metadata recorded (extraction date,
three job IDs, itemids, filter predicates, weight/height join sources). This
exposed THREE factual errors in the manuscript's Methods, all logged as
CRITICAL in Section 9: the stated inclusion criterion (>= 11 SAS) is the
modeling requirement, not the extraction filter (>= 15 SAS and >= 5 propofol
events); an age >= 18 filter is claimed but was never applied; and the
anchor-year age computation is undocumented. All three filter claims were
verified directly against the extract, which shows hard floors at exactly 15
and exactly 5. Reconstructing the feature build from the raw CSVs also
established where the 1,490 -> 1,489 patient goes and how much data the
72-hour simulation window silently discards. The query TEXT is still not in
the repo; only the metadata was recovered.

--- Sep 2026: EC50 pinning diagnosed ---
08_ec50_diagnostics.py established that EC50 boundary pinning has TWO separate
causes, neither pharmacological. Pinned-low (52%) is the exposure problem: 10x
lower Ce than interior patients, and 95.5% have no interior optimum at all.
Pinned-high (45 patients) is a bug: they are exactly the patients whose
calibration window contributed zero usable points, so the objective is
identically flat and scipy terminates at 9.999995. The brief expected pinning
to track sedation level; it does not, the groups differ by 0.25 SAS units.
What matters is that every group sits ~3.4 SAS units below the Eleveld E0=7
drug-free baseline, so EC50 is absorbing a scale mismatch. Recorded in
Section 11.5. Diagnostic only, nothing was re-fitted.

--- Sep 2026: cohort figures, and the persistence baseline problem ---
05_cohort_figures.py was written and run, producing the cohort distributions,
Table 1, the per-patient error scatters and the correlations Kahveci asked
for. Per-patient MAE required retraining the 4-unit FULL_HYBRID across all ten
sweep seeds, since only aggregate MAE had ever been saved. The aggregate
reproduced the published 0.3514 to within 0.10 SDs.

Two things surfaced that were not part of the request and matter more than it.
First, a naive persistence baseline beats every model the project has built,
because SAS is unchanged from the previous observation in 78.3% of test

[CRITICAL] A NAIVE PERSISTENCE BASELINE BEATS EVERY MODEL IN THE PROJECT.
    Found 2026-09-03 while computing per-patient errors for the cohort
    figures. This is the most consequential thing in this file. Read it before
    doing any more modelling work.

    Predicting simply "the SAS score will be whatever it was at the last
    observation" -- that is, returning the sas_last feature unchanged, with no
    training of any kind -- scores better on the identical test split than
    anything the project has built:

        method                              test MAE (instance-weighted)
        persistence (predict sas_last)          0.2866
        4-unit FULL_HYBRID LSTM (best in sweep) 0.3514
        best XGBoost (FULL_HYBRID ablation)     0.3330
        window mean (predict sas_mean)          0.4699
        global train mean                       0.7316

    Persistence is 18.4% better than the best LSTM and 13.9% better than the
    best XGBoost. Paired over the 298 test patients it wins decisively:
    model 0.3395 vs persistence 0.2769 patient-weighted, Wilcoxon
    p = 9.4e-19, with the model ahead for only 72 of 298 patients (24.2%).

    WHY: SAS is unchanged from the previous observation in 78.3% of test
    instances. Persistence scores exactly zero error on all of them. The
    prediction task as currently framed is dominated by a signal the models
    are given (sas_last is a CLINICAL feature present in every configuration,
    PURE_ML included) and then degrade rather than exploit.

    Corroborating evidence from the same analysis: per-patient MAE correlates
    rho = 0.851 (p = 8.5e-85) with how variable that patient's SAS actually
    is. Broken down by within-patient SAS variability:
        SAS constant (n=74, 24.8% of test patients)   mean MAE 0.0984
        std 0-0.5    (n=82)                           mean MAE 0.2311
        std 0.5-1    (n=109)                          mean MAE 0.4528
        std >1       (n=33)                           mean MAE 0.7756
    Aggregate MAE is therefore mostly a statement about how many easy,
    non-varying patients are in the split, not about model quality.

    WHAT THIS DOES AND DOES NOT INVALIDATE:
    - It does NOT directly invalidate the capacity-moderation finding. That is
      a RELATIVE comparison between feature configurations at matched
      capacity, and removing mechanistic features still degrades small LSTMs
      more than large ones regardless of where the absolute floor sits.
    - It DOES invalidate any clinical framing that says the hybrid approach
      improves ICU sedation prediction. It does not improve on doing nothing.
    - Reviewers at a clinical venue will ask for a persistence baseline. It is
      the standard baseline for slowly-varying clinical time series. Better to
      report it than to be caught without it.

    OPTIONS, none of them free:
    (a) Report persistence honestly and reframe the contribution as purely
        methodological, about capacity and inductive bias, with an explicit
        statement that no configuration beats persistence on this task.
    (b) Change the prediction target to something persistence cannot solve:
        predict the CHANGE in SAS, or predict only at instances where a change
        occurs, or forecast further ahead than the next observation. This is a
        real experiment, not a rewording, and would mean rerunning everything.
    (c) Evaluate on the 21.7% of instances where SAS actually changes.
        Persistence scores MAE 1.3235 there, so there is real headroom, but
        conditioning the test set on the target is a leak unless handled
        carefully and a reviewer will scrutinise it.
    My recommendation is (a) plus (b) as the next experiment. Do not publish
    the clinical framing without one of these.

    Reproduce with: python src/05_cohort_figures.py
    Outputs: cohort_baseline_comparison.csv

--- 11.1 THE 72-HOUR WINDOW IS AN OBSERVATION FILTER ---

sim_duration_hrs=72 is recorded in Section 5 as an ODE solver setting. It is
not only that. Every SAS observation is indexed relative to the patient's FIRST
propofol infusion event, and anything outside [0, 72] hours is dropped. Of
113,536 extracted SAS observations:

    disposition                      count      share
    before the first infusion        8,919       7.9%   discarded
    after the 72-hour window        62,426      55.0%   discarded
    inside the window               42,191      37.2%   usable

    Total discarded: 71,345 observations, 62.9% of everything extracted.

603 of 1,489 patients lose MORE THAN HALF of their SAS observations this way.

This is a cohort-defining filter. It determines both which observations become
prediction instances and, in at least one case, which patients exist in the
analysis at all. It should appear in Methods as an inclusion criterion
alongside the SQL filters, not buried in a solver-settings table.

Note also the asymmetry: the window is anchored to the first propofol event,
not to ICU admission. A patient sedated late in a long stay has their whole
pre-sedation history discarded by the 7.9% bucket, which is intended, but a
patient on a long or intermittent sedation course loses the tail, which is a
selection effect toward early-stay observations. Say so.

--- 11.2 ZERO-FILL IMPUTATION IN THE Ce SEQUENCES ---

When a step of an LSTM Ce history sequence falls outside the 72-hour window,
01_build_features.py does NOT drop the instance. It appends a literal 0.0:

    ce_history.append(0)   # else-branch of the window check

That is a fabricated zero drug concentration presented to the model as if it
were a simulated one, and 0.0 is not a neutral filler here: it is a physically
meaningful value meaning "no drug on board".

    16,784 of 309,310 Ce sequence steps = 5.4% are fabricated zeros.

The target observation is always inside the window; only history steps can be
zero-filled. The affected instances are concentrated at the start of each
patient's usable range. Record as a known limitation. If a reviewer asks
whether the LSTM's temporal mechanistic signal is real, this is the first
thing they will point at, because a spurious zero is exactly the kind of
artifact a recurrent model can latch onto.

The clean fix, if it is ever worth rerunning: drop instances whose history is
not fully inside the window, or mask those steps rather than zero-filling.
That would cost some instances and require regenerating everything downstream,
so it is a decision, not an obvious correction.

--- 11.3 THE SILENT 1,490 -> 1,489 PATIENT DROP ---

The SQL extract contains 1,490 patients. The analysis cohort is 1,489.

step01.log reports "Processed 1490 patients successfully, 0 skipped" and then
"Unique patients in final dataset: 1489". Both lines are correct and they
contradict each other in appearance only: the n_failed counter in
01_build_features.py increments only on the early-return paths (too few SAS
observations, no propofol events, failed simulation). A patient can pass all
of those and still produce zero instances inside the per-observation loop,
where the window check is a bare `continue`. Nothing counts that.

The lost patient is stay_id [stay_id withheld]:

and first_day_height, so both can be NULL. 01_build_features.py substitutes

    field    missing in extract      substituted value    consequence
    weight   18 / 1490  ( 1.2%)      75 kg                feeds the PK rate

The height rate is the one to disclose. Over a quarter of the cohort carries an
identical constant in a feature the models are free to use, which makes
"height" partly an indicator of missingness rather than a measurement. The
weight default is rarer but more consequential per patient, because it
propagates through the PK simulation rather than sitting in a feature vector.

Neither default is mentioned in the manuscript. Both belong in Methods, and the
height figure belongs in Limitations.

--- 11.4.1 POPULATION-EC50 BASELINE (Eleveld 2018) ---

The clinical-practice baseline is the published Eleveld 2018 population model
with EC50 fixed at 3.08 ug/mL for every patient, using the same sigmoid Emax
equation as the paper:

    SAS_hat = E0 - Emax * Ce^gamma / (EC50^gamma + Ce^gamma)

with E0 = 7, Emax = 6, gamma = 1.47. This is deliberately not a fitted patient-
specific calibration; there is no per-patient EC50 optimization in the baseline.
The baseline uses the same effect-site concentration trajectories generated by
the PK model and the same hold-out patient split as the capacity sweep. The
published covariate adjustments are therefore limited to age, sex, weight, and
height as supplied by the feature-generation pipeline; there is no extra
patient-level EC50 fitting or learning step.

Missing covariates were not used as an exclusion criterion: the cohort was not
filtered out for absent weight or height values. In the raw patient table, 18 of
1490 patients (1.2%) have missing weight and 398 of 1490 patients (26.7%) have
missing height; zero patients are missing age or gender. Missing weight was
filled with 75 kg and missing height with 170 cm in 01_build_features.py before
the model is trained or evaluated. This matches the project's standard defaulting
policy and keeps the same patients in the analysis set.

The corresponding population-EC50 baseline therefore represents the current
clinical-practice status quo: a fixed pharmacological response model with the
average adult EC50, not a personalized digital twin.

--- 11.5 EC50 BOUNDARY PINNING: TWO SEPARATE FAILURES, NEITHER PHARMACOLOGICAL ---

Established 2026-09-03 by src/08_ec50_diagnostics.py (diagnostic only; the
calibration was not modified or re-run). Outputs: ec50_diagnostics.csv,
ec50_patient_level.csv, figures/cohort/ec50_pinning_diagnostics.{png,pdf}.

    pinned-low  (EC50 = 0.5,  the lower bound)   774 patients   52.0%
    pinned-high (EC50 = 10.0, the upper bound)    45 patients    3.0%
    interior                                     670 patients   45.0%
    TOTAL PINNED                                 819 patients   55.0%

For 55% of the cohort, EC50_calibrated is not a fitted parameter. It is the
optimiser reporting that it wanted to leave the search interval. This is the
feature that carries the paper's "patient-specific digital twin" claim.

MECHANISM 1, pinned-low: no drug to calibrate against.
The stated exposure hypothesis is CONFIRMED, decisively.

    variable (median)              pinned-low   interior   Kruskal p
    mean Ce (ug/mL)                   0.0763     0.7871     9.9e-101
    median Ce (ug/mL)                 0.0196     0.5357     8.0e-102
    max Ce reached (ug/mL)            0.4185     1.8441     6.7e-86
    fraction of instances Ce < 0.1    0.7778     0.2000     1.6e-93
    fraction of instances Ce < 0.01   0.3929     0.0000     9.3e-93
    mean propofol rate               0.0000    15.1192     9.0e-67

Interior patients carry 10.3x the effect-site concentration of pinned-low
ones at the median. For a pinned-low patient with Ce ~ 0.08, sigmoid_emax
returns about 6.65 at EC50 = 0.5 and about 7.00 at EC50 = 10, against an
observed SAS near 3.9. The loss therefore decreases monotonically toward the
lower bound and the optimiser rails there while still missing the observation
by roughly 2.7 SAS units. Direct confirmation from profiling the objective on
a grid: 739 of 774 pinned-low patients (95.5%) have no interior minimum at
all. Panel (c) of the figure shows this.

MECHANISM 2, pinned-high: an empty objective. This is a BUG, not a fit.
The exposure hypothesis does NOT explain this group; their drug exposure is
essentially normal (median mean-Ce 0.605 against 0.787 for interior).

    All 45 pinned-high patients are EXACTLY the 45 patients whose calibration
    window contributed zero usable points, and no others. Set identity was
    verified, not inferred.

    Cause: ec50_loss accumulates only calibration observations whose index
    falls inside the 72-hour simulated trajectory, then returns
    loss / max(n, 1). When n = 0 that is 0/1 = 0 for every candidate, so the
    objective is identically flat. scipy's bounded minimize_scalar on a
    constant function terminates at 9.999995, and all 45 patients carry
    exactly that value. Confirmed by running minimize_scalar on a literal
    constant: it returns 9.999995.

    So these 45 EC50 values are a golden-section terminus. They encode
    nothing about the patient. This is the 72-hour window (Section 11.1)
    causing a second, previously unnoticed failure.

THE BRIEF'S SAS HYPOTHESIS IS NOT SUPPORTED.
Pinning does not track how awake or sedated a patient is. Mean SAS is 3.92
(pinned-low), 3.67 (pinned-high), 3.82 (interior): a spread of 0.25 SAS units
across groups. What matters is not the difference between groups but the
distance from the model's own drug-free baseline. Every group sits about 3.3
to 3.5 SAS units BELOW E0 = 7. The Eleveld E0/Emax scale says an ICU patient
with no propofol on board should read 7 (dangerous agitation); these patients
read about 3.5 while sedated by everything else in an ICU. EC50 is absorbing
that baseline mismatch. The right conclusion is that the Eleveld PD scale does
not transfer to ICU SAS without re-anchoring E0, not that these patients have
unusual propofol sensitivity.

IMPACT: the degeneracy costs no accuracy, which is the damning part.
Per-patient MAE, test patients only: pinned-low 0.2125 (n=165), interior
0.3220 (n=122), Mann-Whitney p = 0.038. Pinned-low patients are predicted
MORE accurately, not less. That is confounding rather than benefit: pinned-low
patients are the low-exposure ones whose SAS barely moves, and per-patient
error tracks within-patient SAS variability at rho = 0.85 (Section 9). They
are simply the easy patients.

Both implications belong in the paper:
    - the boundary artefact is not degrading prediction, so there is no
      accuracy argument for fixing it; and
    - a feature that can be degenerate for 55% of the cohort at no cost to
      accuracy is a feature carrying very little signal, which is consistent
      with EC50_calibrated correlating 0.03 with the target and with the
      NO_STATIC_MECH ablation barely moving.

WHAT THIS MEANS FOR THE MANUSCRIPT
The claim that per-patient EC50 calibration produces a patient-specific
digital twin is not supportable as written. For 52% of patients the
calibration had insufficient drug exposure to identify the parameter, and for
another 3% it had no data at all. Options, in increasing order of work:
    (a) Report the pinning honestly and restrict any personalisation claim to
        the 45% of patients with an identifiable interior optimum.
    (b) [IMPLEMENTED 2026-10-07] Fix the n = 0 case so it falls back to
        EC50_pop = 3.08, matching the intent of the exception handler. The
        feature cache must be rebuilt and downstream experiments rerun.
    (c) Re-anchor E0 to something appropriate for ICU SAS, or fit E0 jointly
        with EC50. This is the real fix for mechanism 1 and it is a modelling
        change, not a bug fix.
Do not describe EC50 as patient-calibrated without addressing (a) at minimum.

(b) Keras seeding. Until 2026-10-12 run_lstm called np.random.seed(seed) and

    this and is not reproducible by seed. Rows made with the fixed seeding
    carry seeding = keras.utils.set_random_seed; rows without a seeding column
    are pre-fix. 02b refuses to resume a file that has no seeding column.

12.5 INITIAL-WEIGHT HASH VERIFICATION (630 OF 630)

Every row stores two SHA-256 digests taken after model.compile and before
model.fit:
    init_weights_sha256   all nine weight arrays
    init_shared_sha256    the seven arrays whose shape does not depend on the
                          feature configuration (LSTM recurrent kernel and
                          bias, Dense(16) bias, Dense(8) kernel and bias,
                          output kernel and bias)

Check 1, reproducibility by seed (2026-10-13). For each of the 330 distinct
(configuration, units, seed) combinations the model was rebuilt in a fresh
process from keras.utils.set_random_seed(seed) alone, with no data loaded, and
both digests were recomputed. Result: init_weights_sha256 matches the stored
value in 630 of 630 rows, and init_shared_sha256 in 630 of 630. This covers the
94 session-1 rows, so those were initialised exactly as the committed script
initialises them. The rebuild has to create the layers in the order run_lstm
does, because each layer constructor draws its seed in turn.

Check 2, agreement across processes. 240 (configuration, units, seed)
combinations were trained in more than one arm, by different worker processes.
All 240 carry a single init_weights_sha256.

Check 3, pairing (run by 03d before any paired test). In all 13 comparisons,
all 30 seeds give identical init_shared_sha256 for the configuration and for
PURE_ML. The LSTM input kernel and the Dense(16) kernel differ between
configurations because the feature counts differ, so paired runs share the
seed, the shuffle order and the shape-invariant weights, not the whole model.

What the hashes do not show: that training is bit-reproducible. Only the
initial weights were re-derived; no run was retrained to compare final MAE.
